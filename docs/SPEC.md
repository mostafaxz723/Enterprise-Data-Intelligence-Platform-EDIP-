# 1. الملخص التنفيذي

**أطلس الطاقة المتجددة الحي لمصر** (اسم مبدئي) منصة ويب ذكية تجيب عن ثلاثة أسئلة يحتاجها كل مخطط ومستثمر وصانع قرار في قطاع الطاقة المتجددة: **أين نبني؟ وكم سننتج فعليًا؟ وما المخاطر التي قد تهدد المشروع؟**

تعتمد المنصة على بيانات عالمية مفتوحة تتحدث تلقائيًا (الطقس والغبار والتضاريس والأقمار الصناعية والخرائط)، وتدمجها في خط بيانات هندسي مؤتمت، ثم تحولها بنماذج فيزيائية واقتصادية معروفة، وليس بصناديق سوداء، إلى قرارات مفهومة: ترتيب للمواقع، وتقدير للإنتاج مع نطاق عدم يقين، وتكلفة تقريبية للكيلوواط ساعة، وتفسير بالعربي لسبب كل نتيجة.

| البند | الوصف |
|---|---|
| المشكلة | دراسات اختيار المواقع بطيئة ومكلفة، والأطالس العالمية تعطي الموارد فقط (إشعاع، رياح) دون الغبار والشبكة والسيول والطيور والتكلفة، فيصعب على غير المتخصص اتخاذ قرار. |
| الحل | منصة تدمج الطقس الحي مع طبقات GIS عالمية في شبكة سداسية موحدة (H3)، وتحسب الإنتاج بنماذج فيزيائية، وترتب المواقع حسب تكلفة الكيلوواط ساعة والمخاطر. |
| المستخدمون | الجهات الحكومية (مثل وزارة الكهرباء والطاقة المتجددة، وهيئة الطاقة الجديدة والمتجددة، والشركة المصرية لنقل الكهرباء)، والمستثمرون والمطورون، والباحثون والطلاب، والإعلام والمواطنون المهتمون. |
| عناصر التميز | الغبار داخل حساب الإنتاج، والتكامل بين الشمس والرياح بالساعة، والشبكة داخل القرار، وفلتر السيول والطيور، والتوقع التشغيلي لـ 72 ساعة، ونطاقات الثقة، وأوزان يضبطها المستخدم. |
| المخرجات | موقع عربي منشور على الإنترنت، وواجهة API، ومساعد ذكي يشرح النتائج، ومحاكاة ثلاثية الأبعاد، وتقارير PDF، ووثائق منهجية. |
| الأساس التقني | Airflow وPostGIS وParquet/Zarr وdbt وFastAPI وNext.js وMapLibre وdeck.gl وpvlib وwindpowerlib وClaude API. |
| حدود المشروع | أداة دعم قرار على مستوى التخطيط الأولي، وليست دراسة جدوى مصرفية (bankable) ولا بديلًا عن القياسات الميدانية. |

> **كيف تقرئين هذه الوثيقة**
> الوثيقة حية وتتحدث مع تقدم العمل. أي معلومة وُسمت بعلامة **[تحقق]** يجب مراجعتها من المصدر الرسمي قبل الاعتماد عليها (أرقام، أسعار، شروط استخدام، روابط).
> المعادلات والقيم الرقمية في القسم 5 افتراضات هندسية شائعة قابلة للمعايرة، وليست لوائح رسمية.

# 2. السياق والمشكلة والفجوة

## 2.1 لماذا مصر ولماذا الآن؟

- تتمتع مصر بإشعاع شمسي من الأعلى عالميًا خاصة في الصعيد والصحراء الغربية، وبرياح قوية في خليج السويس والبحر الأحمر. وتضم مشروعات كبرى مثل مجمع بنبان للطاقة الشمسية في أسوان ومحطات الرياح في الزعفرانة وجبل الزيت ورأس غارب.
- للدولة أهداف معلنة لرفع حصة الطاقة المتجددة في مزيج الكهرباء (ضمن استراتيجية الطاقة المستدامة حتى 2035، ويتردد رقم نحو 42%) **[تحقق من الرقم الحالي]**، وكل ميجاوات متجدد يوفر وقودًا أحفوريًا وغازًا قابلًا للتصدير.
- الطلب الصيفي على الكهرباء مرتفع بسبب التكييف، وارتفاع الحرارة يخفض كفاءة الألواح والخطوط معًا، ما يجعل التخطيط المبني على الطقس مهمًا.

## 2.2 المشكلات التي تعالجها المنصة

- **بطء اختيار المواقع:** تجميع بيانات الموارد والأراضي والشبكة يدويًا يستغرق شهورًا ويكلف كثيرًا.
- **إهمال الغبار:** العواصف الترابية وتراكم الغبار يخفضان الإنتاج، وأغلب أدوات التقييم تفترض ألواحًا نظيفة.
- **البعد عن الشبكة:** موقع ممتاز الإشعاع قد يصبح غير مجدٍ إذا كانت تكلفة الربط عالية.
- **المخاطر الطبيعية:** السيول المفاجئة في الأودية قد تدمر منشآت، وممرات هجرة الطيور في خليج السويس قيد حقيقي على مواقع الرياح.
- **التقطع (intermittency):** الشمس والرياح متغيران؛ ومعرفة تكاملهما ساعة بساعة تقلل حاجة التخزين.
- **صعوبة الفهم:** نتائج الدراسات الفنية لا يستطيع صانع القرار غير المتخصص قراءتها بسهولة.

## 2.3 الفجوة بين الأدوات الموجودة وما نقدمه

| الأداة / الأسلوب | ما تقدمه | ما ينقصها | ما نضيفه |
|---|---|---|---|
| Global Solar Atlas | متوسطات طويلة المدى للإشعاع وإنتاج الألواح بدقة عالية | لا غبار حي، ولا شبكة ولا سيول ولا ترتيب اقتصادي | ندمجها كمرجع ونبني فوقها الطبقات التشغيلية |
| Global Wind Atlas | سرعة الرياح وكثافة القدرة بدقة نحو 250 م | لا ربط بالشبكة ولا قيود الطيور ولا توقع حي | نستخدمها لتصحيح ERA5 محليًا |
| PVGIS | حاسبة إنتاج الألواح لنقطة واحدة | نقطة بنقطة، بلا ترتيب لمساحات واسعة ولا قيود | نقارن بها للتحقق من نتائجنا |
| دراسات الجدوى التقليدية | دقة عالية لموقع محدد | بطيئة ومكلفة ولا تقارن مواقع كثيرة | فرز أولي سريع لآلاف المواقع قبل الدراسة المفصلة |

## 3.1 كيف نقيس الأثر دون ادعاءات غير مدعومة

# 5. المفهوم النظري والمعادلات

هذا القسم يشرح الفيزياء والاقتصاد وراء كل رقم. الهدف أن يكون كل ناتج في المنصة قابلًا للتتبع إلى معادلة ومصدر بيانات، وهذا ما يميز المشروع عن النماذج المغلقة.

## 5.1 الإشعاع الشمسي

- **GHI:** الإشعاع الكلي الأفقي. **DNI:** الإشعاع المباشر العمودي على أشعة الشمس. **DHI:** الإشعاع المنتشر على سطح أفقي.
- **POA:** الإشعاع الواصل فعليًا لسطح اللوح المائل أو المتتبع، وهو الذي يحدد الإنتاج.

```
GHI = DNI × cos(θz) + DHI
```
θz زاوية سمت الشمس (Zenith). نحسب موضع الشمس بدقة عبر pvlib لكل ساعة.

```
POA = POA_beam + POA_sky_diffuse + POA_ground_diffuse
```
نحول من GHI/DNI/DHI إلى POA بنماذج مثل Hay-Davies أو Perez، ونقارن الثابت بالمتتبع أحادي المحور.

## 5.2 إنتاج الألواح الكهروضوئية

```
T_cell = T_amb + G_POA / (U0 + U1 × WS)
```
نموذج Faiman لحرارة الخلية؛ بديله المبسط T_cell = T_amb + (NOCT − 20)/800 × G_POA.

```
P_dc = P_STC × (G_POA / 1000) × [1 + γ × (T_cell − 25)]
```
γ معامل الحرارة، وهو عادة نحو −0.3 إلى −0.4% لكل °م للسيليكون البلوري **[تحقق من ورقة بيانات اللوح]**.

```
P_ac = min( P_dc × η_inv , P_ac,max )
```
القص (clipping) عند نسبة DC/AC عالية، وهي ممارسة شائعة في المحطات الكبيرة.

```
CF = E_annual / ( P_nom × 8760 )
```
معامل السعة. ويُعبر عن الإنتاج النوعي بوحدة kWh/kWp في السنة.

**جدول الفواقد المقترح (قابل للمعايرة):**

| الفاقد | كيف يُحسب | ملاحظة |
|---|---|---|
| الحرارة | من معامل γ وحرارة الخلية | مهم جدًا في الصيف المصري |
| الغبار (Soiling) | نموذج تراكم وأمطار (القسم 5.3) | يتغير مع الفصل والموقع |
| انعكاس وتظليل متبادل | هندسة الصفوف وزاوية الشمس | للمتتبعات يتطلب backtracking |
| الأسلاك وعدم التطابق والعاكس | نسب ثابتة معلنة | افتراضات قياسية 1–3% لكل بند |
| الجاهزية والتدهور | نسبة جاهزية وتدهور سنوي | تدهور شائع نحو 0.5% سنويًا **[تحقق]** |

## 5.3 الغبار وجدولة التنظيف

نستخدم نموذجين: نموذج خطي مبسط (Kimber) يفترض خسارة تتراكم بمعدل ثابت يوميًا وتنتهي عند مطر يتجاوز عتبة، ونموذج HSU الذي يربط الترسب بتركيز PM2.5 وPM10. نعايرهما بقيم من الأدبيات ونتركهما قابلين للضبط (pvlib.soiling).

```
L(t) = min( L_max , r × (t − t_clean) )
```
L خسارة الغبار، r معدل التراكم اليومي، t_clean آخر تنظيف أو مطر فعّال.

**الفترة المثلى بين التنظيفين:** إذا كانت تكلفة التنظيف C، والإيراد اليومي للألواح النظيفة R_d، تقل التكلفة المتوسطة اليومية عند:

```
T* = √( 2C / ( r × R_d ) )
```
نشتقه من تصغير f(T) = C/T + r·R_d·T/2. ويعطي التوصية الشخصية لكل موقع بدل جدول موحد.

## 5.4 طاقة الرياح

بيانات ERA5 تعطي مركبات الرياح عند 100 م (u100 وv100) بدقة نحو 31 كم، ولا تلتقط تأثير التضاريس المحلي، لذا نصححها بأطلس الرياح العالمي (250 م) كما في القسم 9.

```
v(h) = v_ref × ln(h / z0) / ln(h_ref / z0)
```
قانون اللوغاريتم لتغير السرعة مع الارتفاع، z0 طول خشونة السطح. وبديله قانون القوة v = v_ref (h/h_ref)^α.

```
ρ = p / ( R × T )   ،   R = 287.05 J/(kg·K)
```
كثافة الهواء تقل مع الحرارة والارتفاع، فتقل الطاقة عند نفس السرعة.

```
P = ½ × ρ × A × Cp × v³   ،   Cp ≤ 16/27 ≈ 0.593
```
حد بيتس. والمنحنى الفعلي للتوربين (power curve) له سرعة بدء وسرعة اسمية وسرعة قطع.

```
f(v) = (k/c) × (v/c)^(k−1) × exp( −(v/c)^k )   ،   AEP = 8760 × ∫ P(v) f(v) dv
```
توزيع ويبل للسرعات والإنتاج السنوي المتوقع. ونحسب فواقد الأثر الانسيابي (Wake) والجاهزية والكهرباء.

نستخدم مكتبة windpowerlib مع منحنيات توربينات حقيقية متاحة فيها، ونعرض المحاكاة بتوربين مرجعي معلن.

## 5.5 التكامل بين الشمس والرياح (الهجين)

- نحسب لكل خلية سلسلتين ساعيتين لمعامل السعة: CF_s وCF_w.
- **الارتباط:** معامل بيرسون ρ بين السلسلتين؛ كلما قل أو صار سالبًا زاد التكامل.
- **التقلب:** نبحث عن النسبة α التي تقلل معامل التباين للمزيج.
- **القدرة المؤكدة:** مستوى الإنتاج المتجاوز في 90% من الساعات، ومعدلات الصعود والهبوط (ramp rates).
- **حجم التخزين التقريبي:** أكبر عجز تراكمي بين الإنتاج ومستوى مستهدف ثابت.

```
CF_h = α × CF_s + (1 − α) × CF_w   ،   CV = σ(CF_h) / μ(CF_h)
```
نختار α التي تصغر CV تحت قيود تكلفة وأرض.

## 5.6 الاقتصاد: تكلفة الكيلوواط ساعة (LCOE)

```
CRF = r × (1 + r)^n / ( (1 + r)^n − 1 )
```
عامل استرداد رأس المال؛ r معدل الخصم (WACC) وn عمر المشروع.

```
LCOE ≈ ( CAPEX × CRF + OPEX_fix ) / ( 8760 × CF )
```
الصيغة المبسطة للفرز. والصيغة الأدق: مجموع التكاليف المخصومة ÷ مجموع الطاقة المخصومة مع التدهور.

```
CAPEX_total = CAPEX_plant + d_grid × c_line + C_substation
```
تكلفة الربط: مسافة أقرب خط جهد مناسب × تكلفة الكيلومتر + المحطة، وهذا ما يغير الترتيب فعليًا.

نأخذ التكاليف من مراجع عامة (IRENA وNREL ATB وعطاءات مصرية معلنة) كنطاقات، ونعرض تحليل حساسية على r وCAPEX **[تحقق من أحدث الأرقام]**.

## 5.7 ملاءمة المواقع: القيود ثم الاقتصاد ثم المخاطر

نعتمد ثلاث مراحل بدل مجموع أوزان واحد، حتى لا يخفي رقم واحد مشكلة قاتلة:

1. **استبعاد صارم (Boolean):** محميات، مياه، مدن وقرى مع حرم، أراضي زراعية، ميل زائد، مجاري أودية مع حرم.
2. **اقتصاد فني:** حساب الإنتاج وLCOE لكل خلية متبقية.
3. **درجة مخاطر وملاءمة:** مجموع موزون S = Σ(w_i × x_i) لعوامل مطبعة (0–1) كالحساسية البيئية والوصول والسيول، ويضبط المستخدم الأوزان.

لاشتقاق الأوزان الافتراضية نستخدم **AHP**: مصفوفة مقارنات زوجية ثم المتجه الذاتي، ونقبل الأوزان إذا كانت نسبة الاتساق CR = CI/RI أقل من 0.1، حيث CI = (λmax − n)/(n − 1).

| العامل | عتبة افتراضية (قابلة للتعديل) | المصدر |
|---|---|---|
| ميل الأرض – شمسي | نحو 3–5° كحد أقصى للثابت | Copernicus DEM |
| ميل الأرض – رياح | نحو 10–15° كحد أقصى | Copernicus DEM |
| نوع الغطاء | استبعاد زراعة ومياه ومباني، وقبول أرض جرداء | ESA WorldCover |
| المحميات | استبعاد مع حرم | WDPA |
| القرى والمدن | حرم 1–2 كم للرياح (ضجيج وظل)، وأقل للشمس | GHSL / OSM |
| مجاري الأودية | استبعاد المجرى وحرم حوله | تحليل DEM (القسم 5.8) |
| قرب الطرق والشبكة | كلما قل البعد قلت التكلفة | OSM |

هذه العتبات تقديرات شائعة في أدبيات تحليل المواقع، وليست لوائح مصرية رسمية، وتُراجع مع جهة مختصة.

## 5.8 السيول والتضاريس

- نحسب الميل واتجاه الانحدار من DEM، ثم اتجاه التدفق (D8) وتراكم التدفق لاستخراج شبكة الأودية.
- مؤشرات: **HAND** (الارتفاع فوق أقرب مجرى) و**TWI** (مؤشر الرطوبة الطبوغرافي).

```
TWI = ln( a / tan β )
```
a مساحة التجميع النوعية، β الميل.

- نربط ذلك بأمطار IMERG وERA5 لتقدير خطر السيل، **كتقدير مبني على الطقس والتضاريس وليس محاكاة هيدروليكية كاملة**.

## 5.9 الطيور المهاجرة

يُعد خليج السويس من أهم ممرات هجرة الطيور المحلقة بين أوروبا وأفريقيا. ندخل طبقة حساسية (قرب مناطق الطيور المهمة IBA وممرات الهجرة) كقيد أو عامل خطر، ونقترح إجراءات تخفيف مثل الإيقاف عند الطلب. توفر هذه البيانات وشروط استخدامها يجب التأكد منه **[تحقق]** قبل إدراجها.

## 5.10 عدم اليقين والتحقق الإحصائي

- **تصحيح الانحياز:** مطابقة التوزيعات (quantile mapping) بين ERA5 والمرجع المحلي.
- **النطاقات:** مجموعات توقعات متعددة (ensembles) أو انحدار كمّي (LightGBM quantile) أو conformal prediction.
- **المقاييس:** MAE وRMSE وnMAE = MAE / P_nom والانحياز والارتباط، و**مهارة التوقع** مقارنة بنموذج الثبات (persistence).

```
Skill = 1 − MSE_model / MSE_persistence
```
قيمة موجبة تعني أن النموذج يتفوق على «الغد مثل اليوم».

```
P90 = P50 × ( 1 − 1.2816 × σ_total )   ،   σ_total = √( Σ σ_i² )
```
تقريب طبيعي: كل مصدر عدم يقين (بيانات، نموذج، فواقد) يُجمع تربيعيًا.

## 7.2 مبادئ التصميم الاحترافي

- **الإعادة الآمنة (Idempotency):** إعادة تشغيل أي مهمة لنفس التاريخ لا تكرر البيانات (كتابة بتقسيم/upsert).
- **إعادة ملء التاريخ (Backfill):** كل DAG يقبل فترة زمنية ويعيد معالجتها.
- **فصل الخام عن المحسوب:** الخام لا يُعدل؛ كل شيء مشتق يمكن إعادة بنائه بالكامل.
- **عقود البيانات:** مخططات Pandera ومخططات dbt tests عند كل حد بين الطبقات.
- **النسب (Lineage):** وثائق dbt المولدة تُظهر من أين أتى كل جدول.
- **الإعدادات خارج الكود:** ملف YAML للإعدادات و.env للأسرار، ولا مفاتيح في Git.
- **قابلية إعادة الإنتاج:** نسخة مثبتة من المكتبات، وبيئة Docker، وسجل إصدارات للبيانات الثابتة.

| واجهة | Next.js, React, TypeScript, Tailwind, shadcn/ui, next-intl | الموقع العربي RTL | خط Cairo أو Tajawal |
| خرائط الواجهة | MapLibre GL JS, deck.gl, react-map-gl | خرائط 2D/3D وطبقات H3 | H3HexagonLayer للخلايا |
| رسوم | Recharts / ECharts, D3 | منحنيات وإحصاءات | دعم RTL يحتاج ضبطًا |
| 3D | three.js + react-three-fiber + drei, SunCalc | مجسمات ومحاكاة الشمس والرياح | نماذج glTF خفيفة |

| مراقبة | Sentry, UptimeRobot, Grafana | الأخطاء والتوفر | Prometheus/Grafana موجودان في الـ compose |

> **ملاحظات هندسية مهمة**
> **صورة postgis الرسمية لا تتضمن pgvector.** إما نستخدم صورة تحتوي الاثنين، أو قاعدة منفصلة، أو نبدأ بـ Chroma ثم ننتقل.

> Kafka غير لازم في النسخة الأولى (بياناتنا دفعات)، ويُضاف فقط إذا استقبلنا قراءات لحظية فعلية.

# 9. التعلم الآلي والمعايرة

**الفيزياء تحسب، والتعلم الآلي يصحح ويقدّر عدم اليقين.** لا نستبدل pvlib وwindpowerlib بنموذج صندوق أسود، لأن ذلك يضعف التفسير ويصعب الدفاع عنه أمام لجنة تحكيم أو جهة حكومية.

## 9.1 أدوار التعلم الآلي (وحدودها)

| الدور | الطريقة | الفائدة |
|---|---|---|
| تصحيح انحياز الرياح محليًا | معامل مقياس من أطلس الرياح (متوسط محلي ÷ متوسط ERA5) ثم مطابقة التوزيعات | تعويض عدم التقاط ERA5 للتضاريس |
| تصحيح انحياز الإشعاع والغبار | مقارنة مع POWER/PVGIS وتصحيح كمي | تقليل الانحياز المنهجي |
| نطاقات الثقة | انحدار كمي LightGBM أو conformal prediction | P10/P50/P90 لكل توقع |
| توصية التنظيف | تحسين على سلسلة التراكم (القسم 5.3) مع سيناريوهات مطر وغبار | جدول لكل موقع |
| تفسير النموذج | SHAP لنماذج التصحيح | عرض أسباب انحراف التوقع |

> **ما لا نفعله**
> لا نتنبأ بإنتاج محطة من الصفر بنموذج تعلم آلي دون فيزياء.
> لا ندّعي دقة لا نقيسها، ولا نخلط بيانات التدريب بالاختبار.

## 9.2 منهجية التدريب والتقييم

1. **التقسيم الزمني:** تدريب على سنوات واختبار على سنة لاحقة (لا خلط عشوائي) لتفادي تسريب المستقبل.
2. **خط الأساس:** نموذج الثبات (persistence) ونموذج الفيزياء بلا تصحيح.
3. **المقاييس:** MAE وRMSE وnMAE والانحياز والارتباط والمهارة، لكل فصل ولكل منطقة.
4. **التتبع:** MLflow لكل تجربة (البيانات، المعاملات، النتائج) مع بطاقة نموذج (Model Card).
5. **الضبط:** Optuna ضمن حدود زمنية مع التحقق المتقاطع الزمني.
6. **المراقبة بعد النشر:** مقارنة التوقع بالواقع الإعادي (ERA5 لاحقًا) لاكتشاف الانجراف.

## 9.3 خطوة التصحيح المحلي للرياح بالتفصيل

```
v_local(t) = v_ERA5(t) × ( μ_GWA / μ_ERA5 )
```
نضرب السلسلة الساعية بنسبة المتوسط المحلي من أطلس الرياح (250 م) إلى متوسط ERA5 للخلية، ثم نطابق التوزيع إن لزم.

هذا يحتفظ بالتغير الزمني الحقيقي (من ERA5) ويستعير الحجم المكاني من الأطلس. ويجب توثيقه كافتراض يُختبر بالمقارنة مع محطات مصرية معروفة.

# 12. المساعد الذكي (RAG والأدوات)

## 12.1 فكرة المساعد

مساعد بالعربي والإنجليزية يجيب عن أسئلة مثل: «لماذا الموقع س ثالث؟» و«ما أفضل 5 مواقع رياح قرب خليج السويس بعيدًا عن المحميات؟» و«كيف حُسب الغبار؟». ويعتمد على **قناتين معرفيتين** بدل الاعتماد على ذاكرة النموذج:

| القناة | ما تقدمه | كيف |
|---|---|---|
| الأدوات (Function Calling) | أرقام وترتيبات حية من الجداول | دوال مثل get_site(h3_id) وtop_sites(filters) وcompare(sites) وforecast(h3_id) وcalc_lcoe(params) تستعلم من الـ API |
| RAG على الوثائق | المنهجية والافتراضات وقاموس البيانات وأوراق وتقارير سياسات | تقطيع الوثائق وتحويلها لمتجهات وبحث دلالي مع مصادر |

## 12.2 خط معالجة السؤال

1. **فحص النطاق:** هل السؤال عن الطاقة المتجددة في مصر والمنصة؟ وإلا يرفض بلطف.
2. **التوجيه:** هل يحتاج رقمًا (أدوات) أم شرحًا (RAG) أم الاثنين؟
3. **الاسترجاع / الاستدعاء:** استدعاء الدوال أو البحث الدلالي (مع إعادة ترتيب إن لزم).
4. **التوليد المقيد:** الإجابة من نتائج الأدوات والمقاطع المسترجعة فقط، وكل رقم مصدره ظاهر.
5. **التحقق:** التأكد أن الأرقام في النص تطابق مخرجات الأدوات، وإلا يعيد التوليد.
6. **العرض:** إجابة موجزة + «التفاصيل» + المصادر + درجة الثقة والافتراضات.

## 12.3 مكونات تقنية

| المكون | الاختيار المقترح | ملاحظة |
|---|---|---|
| النموذج اللغوي | Claude API (فئة Sonnet للإجابة وفئة أصغر للتوجيه) | أسماء النماذج والأسعار تتغير؛ راجعي docs.claude.com **[تحقق]**. الاستخدام يُحاسب منفصلًا عن اشتراك الشات |
| التضمين (Embeddings) | نموذج متعدد اللغات يدعم العربي (مثل multilingual-e5 أو BGE-M3) | اختبري جودة العربية على أسئلتنا قبل التثبيت |
| مخزن المتجهات | pgvector (مع PostGIS في قاعدة واحدة) أو Chroma للبداية | ابدئي بالأبسط |
| التقطيع | مقاطع 300–600 كلمة مع تداخل وعناوين | اجعلي كل مقطع يحمل عنوان القسم ومصدره |
| التقييم | مجموعة 50–100 سؤال وجواب ذهبي + مقاييس مثل RAGAS ومراجعة بشرية | تتضمن أسئلة خارج النطاق وأسئلة مضللة |

## 12.4 السلامة والتكلفة

- **المفتاح على الخادم فقط**، ولا يصل للمتصفح أبدًا؛ مع تحديد معدل الطلبات لكل مستخدم/IP.
- **حقن التعليمات (Prompt Injection):** نص الوثائق المسترجعة يُعامل كبيانات لا كتعليمات، ولا تُنفذ أوامر داخله.
- **الهلوسة:** عند غياب بيانات يقول «لا أملك بيانات كافية» بدل التخمين.
- **التخزين المؤقت** للأسئلة المتكررة، وحد أقصى للرموز، ومراقبة التكلفة اليومية.
- **الخصوصية:** لا تخزين بيانات شخصية، وتسجيل مجهول لتحسين الجودة.

## 12.5 مثال محادثة

```
User : لماذا الموقع المرتبط بالخلية 3 ثالث في الترتيب؟
Tool : get_site(h3_id) -> factors, lcoe, rank
Bot  : الموقع ثالث لأن موارده الشمسية قوية (2.6 ميجاواط ساعة/كيلوواط ذروة سنويًا)
       لكن بعده عن أقرب خط 220 كيلوفولت (42 كم) رفع تكلفة الربط، فزادت التكلفة التقريبية
       عن الموقعين الأول والثاني. نطاق الثقة: P50–P90. المصادر: Global Solar Atlas, ERA5, OSM.
```

# 13. النشر على الإنترنت والتشغيل

## 13.1 فلسفة «الساكن أولًا» (Static-first)

أغلب ما نعرضه لا يتغير كل ثانية. فنُجري الحسابات الثقيلة **دوريًا خارج الطلب**، وننشر النتائج كملفات (Parquet وJSON وPMTiles) على تخزين كائنات خلف CDN، ويبقى الـ API خفيفًا يجيب الاستعلامات والمساعد فقط. هذا يخفض التكلفة ويرفع السرعة والصلابة أثناء العرض.

| المكون | خيار اقتصادي للتجربة | خيار احترافي |
|---|---|---|
| الواجهة | Vercel أو Cloudflare Pages | نفسهما مع نطاق مخصص وCDN |
| الـ API | Render / Fly.io / Railway أو VPS صغير (Docker) | Cloud Run أو ECS أو VPS مُدار |
| قاعدة البيانات | Postgres مع PostGIS مُدار (مثل Supabase أو Neon أو RDS) **[تحقق من دعم PostGIS]** | RDS/Cloud SQL مع نسخ احتياطي ومراقبة |
| تخزين الملفات والخرائط | Cloudflare R2 أو Backblaze B2 | S3 مع CDN |
| الجدولة | GitHub Actions (cron) للمهام الخفيفة | Airflow على VM بذاكرة كافية (يفضل 4 جيجا أو أكثر) |
| المراقبة | UptimeRobot + Sentry (طبقات مجانية) | Grafana Cloud وتنبيهات |
| النطاق والأمان | نطاق + HTTPS تلقائي من Cloudflare | WAF وقواعد تحديد المعدل |

التكلفة الشهرية للنسخة التجريبية غالبًا من مجانية إلى عشرات الدولارات، وتتغير الأسعار وحدود الطبقات المجانية، فراجعيها وقت النشر **[تحقق]**.

## 13.2 خطوات النشر

1. تحويل كل خدمة إلى صورة Docker مع ملف .env.example، وحفظ الأسرار في متغيرات بيئة المنصة.
2. إعداد CI/CD في GitHub Actions: فحص (ruff/pytest/dbt test) ثم بناء ثم نشر.
3. ترحيل قاعدة البيانات بـ Alembic، وتفعيل امتدادات PostGIS (وpgvector عند الحاجة).
4. تشغيل pipeline التاريخ (backfill) مرة واحدة ثم الجدولة الدورية.
5. رفع PMTiles وJSON إلى التخزين، وضبط ترويسات التخزين المؤقت وCORS.
6. ربط النطاق وتفعيل HTTPS، وإضافة صفحة حالة النظام وآخر تحديث للبيانات.
7. اختبار الحمل (k6 أو Locust) على الـ API ومسار المساعد.
8. نسخ احتياطي تلقائي للقاعدة، وتجربة استعادة فعلية.

## 13.3 قائمة الأمان

- لا مفاتيح في الواجهة أو Git؛ ودوران دوري للمفاتيح.
- تحديد المعدل وCORS مقيد، والتحقق من المدخلات (Pydantic)، وحدود حجم الطلب.
- أقل صلاحيات لمستخدم القاعدة (قراءة فقط للـ API).
- تحديث الصور والمكتبات وفحص الثغرات (Dependabot).
- إخفاء أي مواقع أو بيانات حساسة قد تكون ذات طابع أمني أو عسكري، وعدم ادعاء معرفة بالمناطق المحظورة.

## 13.4 خطة لضمان نجاح العرض الحي

- **وضع لقطة (snapshot mode):** نسخة ثابتة من آخر نتائج تعمل بلا API خارجي إذا تعطل الإنترنت أو مصدر.
- **فيديو عرض مسجل** كاحتياط، وفريق يحفظ سيناريو العرض.
- **تجميد الإصدار** قبل الموعد بأيام، وعدم نشر ميزات جديدة في آخر 48 ساعة.
- اختبار الموقع من شبكة مختلفة وجهاز مختلف وجوال.
